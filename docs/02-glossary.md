# 용어집 — 첫 탑승 조작 실습 (가칭)

- 문서 상태: 초안 v0.1 (2026-11-13)
- 목적: 팀 안에서 같은 대상을 같은 이름으로 부른다. 문서·코드·화면 문구에 아래 이름을 쓴다.
- 코드 식별자는 "코드명" 열을 따른다. 화면에 보이는 말은 "화면 표기" 열을 따른다.

## 1. 제품 구조

| 용어 | 코드명 | 뜻 | 쓰지 않는 말 |
|---|---|---|---|
| **코스** | `Course` | 하나의 기능을 익히는 실습 단위. 예: 김서림 제거 코스. 하나 이상의 단계로 이뤄진다 | 미션, 레슨, 튜토리얼, 퀘스트 |
| **단계** | `Step` | 코스 안에서 한 번의 조작과 그 판정. 예: "앞유리 제상 버튼을 누르세요" | 스텝(문서에서는 "단계"로 통일), 태스크 |
| **묶음** | `Bundle` | 관련 코스를 모은 그룹. 예: 시야 확보 묶음 | 챕터, 카테고리(앱 카테고리와 혼동) |
| **배지** | `Badge` | 묶음의 코스를 모두 완료하면 주는 표시 | 트로피, 점수, 등급, 레벨 |
| **후속 조치** | `FollowUp` | 코스의 조작을 했는데도 원하는 결과가 나오지 않을 때 더 해 볼 수 있는 조작 하나. 예: 김서림 제거 뒤 풍량을 가장 세게. 코스 정의에 순서대로 적어 둔다 | 추천, 팁, 문제 해결, 진단 |
| **후속 조치 안내** | `FollowUpGuide` | 지금 차량 상태를 읽어 아직 하지 않은 후속 조치를 하나씩 안내하고 신호로 판정하는 기능. 사용자가 요청했을 때만 시작한다 | 자동 추천, AI 추천 |
| **소등 확인** | `LightsOffCheck` | 하차 전에 하향등·미등·실내등이 켜져 있는지 읽어 알려 주는 점검. 코스가 아니다(판정할 조작이 없다) | 다크사이트 체크, 소등 인증 |
| **세션** | `Session` | 앱을 열어 실습을 시작한 때부터 앱을 닫거나 주행으로 끊길 때까지의 한 구간 | |
| **코스 정의** | `CourseDefinition` | 코스의 신호, 목표, 오조작 규칙, 안내 문구, 위치 안내 자산을 적은 데이터. 코드와 분리해 둔다 | 콘텐츠, 시나리오 |
| **위치 안내 자산** | `LocatorAsset` | 버튼이 어디 있는지 보여 주는 그림. 기준 차종에 맞춰 직접 제작한다 | 매뉴얼 이미지 |
| **기준 차종** | `referenceModel` | 위치 안내 자산을 만든 대상 차종. MVP는 1종 | |

## 2. 판정

| 용어 | 코드명 | 뜻 |
|---|---|---|
| **판정** | `Verdict` | 단계가 끝났는지를 차량 신호로 결정하는 일. 사용자가 누르는 "완료" 버튼은 없다 |
| **목표 상태** | `targetState` | 단계가 요구하는 신호 값. 예: 앞유리 제상 = On |
| **전이** | `Transition` | 신호 값이 목표가 아닌 값에서 목표 값으로 바뀌는 것. **판정은 상태가 아니라 전이를 본다** |
| **초기 상태 확인** | `Precheck` | 단계를 시작할 때 신호의 현재 값을 먼저 읽는 일. 이미 목표 상태인지 알아내기 위해서다 |
| **조작 조건** | `ActionCondition` | 사용자가 직접 전이를 만들어야 충족되는 조건. 단계마다 하나 이상 |
| **유지 조건** | `HoldCondition` | 완료 시점에 값이 맞기만 하면 되는 조건. 이미 맞아 있으면 조작을 요구하지 않는다. 예: 김서림 제거의 "외기 순환" |
| **조합 판정** | `CombinedVerdict` | 조작 조건과 유지 조건이 모두 충족돼야 완료로 보는 판정 |
| **오조작** | `Misoperation` | 코스 정의에 "이 상태면 목표를 방해한다"고 적어 둔 상태. 예: 김서림 제거 중 내기 순환 |
| **교정 안내** | `Correction` | 오조작을 감지했을 때 그 자리에서 주는 안내 |
| **확인 불가** | `Unverifiable` | 신호를 읽지 못해 판정할 수 없는 상태. 완료로 처리하지 않는다 |
| **허위 완료** | — | 실제로는 조작되지 않았는데 완료로 처리되는 것. **0건이 목표** |
| **기본 조합** | `baseState` | 코스를 완료했을 때의 목표 상태 전체. 후속 조치 안내를 시작할 때 이 상태가 유지되고 있는지 먼저 본다 |
| **해결 확인** | `ResolvedCheck` | 후속 조치 하나가 끝난 뒤 "김이 걷혔나요?"를 묻는 것. 앱은 유리 상태를 알 수 없어 사용자에게 묻는다. 답은 다음에 갈 길을 고르는 데만 쓰고 판정에는 쓰지 않는다 |
| **자기체크** | — | 사용자가 스스로 "했어요"를 누르는 방식. 이 제품이 쓰지 않는 방식이며 비교 대상이다 |

단계의 상태 이름(코드·문서 공통):

| 상태 | 코드명 | 화면 표기 |
|---|---|---|
| 초기 상태 확인 중 | `PRECHECK` | (표시 없음, 짧은 로딩) |
| 이미 목표 상태 | `ALREADY_AT_TARGET` | "이미 켜져 있어요. 한 번 껐다가 다시 켜 보세요" |
| 조작 대기 | `WAITING` | 안내 문구 + 위치 안내 |
| 일부 충족 | `PARTIAL` | "앞유리 제상 확인. 남은 것: 외기 순환" |
| 교정 | `CORRECTION` | 교정 안내 문구 |
| 완료 | `DONE` | "조작 완료" |
| 확인 불가 | `UNVERIFIABLE` | "확인 불가" |
| 건너뜀 | `SKIPPED` | "건너뜀" |

## 3. 차량 신호

| 용어 | 뜻 |
|---|---|
| **신호** | Vehicle SDK로 읽는 차량 상태 값 하나. 예: 에어컨 켜짐, 하향등 상태 |
| **도메인** | Vehicle SDK가 신호를 묶는 단위. 이 제품이 쓰는 도메인: HVAC, Light, Wiper, TurnSignal, Window, Door |
| **지원 여부** (capability) | 그 차량이 해당 신호를 지원하는지. `checkXxxCapabilities`로 확인한다. 미지원이면 코스를 숨긴다 |
| **조회** (get) | 신호의 현재 값을 한 번 읽는 것 |
| **구독** (register) | 신호가 바뀔 때마다 알림(콜백)을 받도록 등록하는 것 |
| **폴링** | 구독이 없는 신호를 일정 간격으로 반복 조회하는 것. 풍향이 해당한다 |
| **순정 버튼** | 차량에 원래 달린 물리 버튼·스위치·순정 화면의 조작부. 사용자가 조작하는 대상 |
| **제상** | 유리의 김·성에를 걷는 기능. SDK 표기는 Defroster. 화면에는 "김서림 제거"(앞유리), "뒷유리 열선"으로 쓴다 |
| **내기 순환 / 외기 유입** | 공조의 공기 순환 모드. SDK·VC 표기는 Recirculate / Fresh |

## 4. 음성

| 용어 | 뜻 |
|---|---|
| **음성 안내** | TTS로 단계 안내와 완료 확인을 읽어 주는 것 |
| **음성 진행** | STT로 고정 어휘를 인식해 단계를 넘기는 것 |
| **고정 어휘** | 앱이 인식하는 세 단어. "다음"(다음으로 넘어감), "다시"(안내를 다시 들음), "어디야"(위치 안내를 다시 보여 주고 읽어 줌). 이 밖의 말은 무시한다 |

"음성 명령"이라는 말은 쓰지 않는다. 차량을 제어하는 음성 명령(Gleo AI)과 혼동되고, STT SDK는 명령 실행 기능이 없다.

## 5. 실행 환경

| 용어 | 뜻 |
|---|---|
| **정차 전용** | 실습 화면이 정차 중에만 열리는 설계 |
| **실습 UI 내림** | 주행 제한이 걸렸을 때 실습 화면을 숨기고 차단 화면으로 바꾸는 동작 |
| **주행 제한** | 차량이 주행 상태라 화면·입력이 제한되는 상태. AAOS `CarUxRestrictionsManager`로 감지한다 |
| **에뮬레이터** | Pleos Connect Emulator. 개발과 2차 PT 시연에 쓴다 |
| **VC** (Virtual Console) | 에뮬레이터의 차량 신호 값을 브라우저에서 바꾸는 도구. 시연에서 "차" 역할을 한다 |

## 6. 프로젝트 내부 식별자

아이디어 선정 단계의 ID와 제품 문서의 ID가 섞이지 않게 한다.

| 표기 | 뜻 | 쓰는 곳 |
|---|---|---|
| C1 | 선정된 조합안 "첫 탑승 조작 실습" (P02 + P06 + P10 + P16) | `docs/reference/`, `archive/` 문서에서만 |
| P02, P06 … | 원래 아이디어 번호 | `docs/reference/`, `archive/` 문서에서만 |
| `CRS-01` ~ `CRS-06` | 실습 코스 ID | 제품 문서·코드 |
| `CHK-01` | 소등 확인 | 제품 문서·코드 |
| `FR-xx` | 기능 요구사항 ID | 기능 명세서 |
| `AC-xx-n` | 수용 기준 ID | 기능 명세서 |
| `SCR-xx` | 화면 ID | 사용자 플로우 |
| `POL-영역-번호` | 정책 ID. 영역: P 원칙, J 판정, R 진행·기록, C 코스 노출, V 음성, D 주행 전환, L 소등 확인, F 후속 조치, S 데이터, E 오류·앱 상태, W 문구, U 화면 | 정책서 |

## 7. 쓰지 않는 말 (요약)

| 쓰지 않는 말 | 대신 쓰는 말 | 이유 |
|---|---|---|
| 점수, 등급, 랭킹, 레벨 | 조작 완료, 배지 | 공식 예시 "안전운전 점수"와 겹쳐 보인다 |
| 미션, 퀘스트 | 코스 | 게임 앱으로 읽힌다 |
| 매뉴얼, 설명서 | 실습, 안내 | 정보 제공형과 구분한다. "매뉴얼(대용량 텍스트)"은 주행 중 금지 분류이기도 하다 |
| 음성 명령 | 음성 진행, 고정 어휘 | 차량 제어 명령과 혼동 |
| 완전 소등, 소등 인증 | 소등 확인 | 읽을 수 없는 등이 있다 |
| 최초, 유일 | (쓰지 않음) | 선행 사례가 없다는 확인이 아니다 |
| 자동으로 켜 드립니다 | (쓰지 않음) | 앱은 차량을 제어하지 않는다 |
