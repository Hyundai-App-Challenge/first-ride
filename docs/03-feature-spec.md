## 0. 읽는 법

**우선순위**

| 등급 | 뜻 |
|---|---|
| **Must** | 없으면 제품이 성립하지 않는다. 2차 PT 시연본에 반드시 들어간다 |
| **Should** | 2차 PT 시연본에 넣는 것이 목표다. Must가 모두 수용 기준을 통과한 뒤 착수한다 |
| **Could** | 여유가 있을 때만. 빠져도 시연과 기획서 메시지에 영향이 없다 |

우선순위는 만드는 순서이지 품질을 낮춰도 된다는 뜻이 아니다. 어떤 등급이든 **수용 기준을 전부 통과해야 "완료"** 이고, 통과하지 못한 기능은 빌드에서 뺀다.

**"11-15" 열**: 접수 제출본(release APK·영상)에 포함하는지. ● 필수 / ○ 통과하면 포함 / — 미포함

**수용 기준 검증**: 별도 표기가 없으면 에뮬레이터 + Virtual Console(VC)에서 값을 바꿔 확인한다.

## 2. 기능 상세

### FR-01. 앱 시작·차량 연결·지원 여부 확인 — Must

**동작**
1. 앱을 열면 `Vehicle.initialize()`로 차량 서비스에 연결한다.
2. 코스 정의에 적힌 모든 신호에 대해 `checkXxxCapabilities`로 지원 여부를 확인한다.
3. 필수 신호가 하나라도 미지원인 코스는 목록에서 숨긴다.
4. 연결과 확인이 끝나면 홈(SCR-02)으로 간다.

**수용 기준**
- AC-01-1: 앱 실행부터 홈 표시까지 10초 이내다(Pleos 심사 기준). 2초를 넘기면 진행 표시가 보인다.
- AC-01-2: 필수 신호가 미지원인 코스는 홈에 보이지 않는다. (검증: 지원 여부 결과를 미지원으로 바꾼 단위 테스트)
- AC-01-3: 지원되는 코스가 하나도 없으면 "이 차량에서는 실습할 수 있는 기능이 없습니다"를 보여 주고 빈 목록을 보여 주지 않는다.
- AC-01-4: 차량 서비스 연결에 실패하면 FR-12의 연결 오류 화면으로 간다. 홈으로 가지 않는다.
- AC-01-5: 매니페스트에는 조회 퍼미션(`CAR_CLIMATE`, `CAR_LIGHTS`, `CAR_WINDOWS`, `CAR_DOORS` 중 빌드에 든 코스가 쓰는 것)과 음성 퍼미션(`TTS_SERVICE`, `STT_SERVICE`)만 선언한다. 제어 퍼미션(`CONTROL_CAR_*`)과 인터넷 퍼미션은 선언하지 않는다. 퍼미션 이름은 Pleos 문서에서 확인했다(기술 설계 10-1절).

### FR-02. 판정 엔진 — Must

제품의 핵심이다. 모든 코스가 이 엔진 하나를 쓴다.

**단계 한 개의 처리 순서**

1. **초기 상태 확인**: 단계의 모든 조건 신호를 조회(get)한다.
2. **구독 시작**: 조건 신호를 구독(register)한다. 구독이 없는 신호(풍향)는 폴링한다.
3. **조작 조건 판정**: 조작 조건의 신호가 *목표가 아닌 값 → 목표 값*으로 전이했고 지금 값이 목표 값이면 충족이다. 충족은 고정되지 않는다. 값이 다시 목표 밖으로 나가면 미충족으로 돌아간다(정책서 POL-J-3, POL-J-4).
   - 시작할 때 이미 목표 값이면 `ALREADY_AT_TARGET` 상태가 된다. 사용자가 값을 목표 밖으로 바꿨다가 다시 목표로 돌리면 충족이다.
4. **유지 조건 판정**: 현재 값이 목표 값이면 충족이다. 이미 맞아 있으면 조작을 요구하지 않는다.
5. **오조작 감지**: 코스 정의의 오조작 규칙에 해당하는 상태면 교정 안내를 낸다. 교정을 내는 때는 두 가지다. (a) 조작 조건이 충족됐는데 오조작 상태가 남아 있을 때 (b) 단계 진행 중에 신호가 오조작 값으로 바뀌었을 때. 시작할 때부터 오조작 상태였고 아직 조작 조건의 전이가 없으면 교정을 내지 않는다. 주 조작을 먼저 안내하기 위해서다.
6. **완료**: 조작 조건과 유지 조건이 모두 충족된 순간 `DONE`.
7. **확인 불가**: 조회 실패, 콜백의 `onFailed`, 오류코드, 응답 시간 초과가 발생하면 `UNVERIFIABLE`. 완료로 처리하지 않는다.
8. 단계가 끝나거나 화면을 떠나면 구독을 해제(unregister)하고 폴링을 멈춘다.

**수용 기준**
- AC-02-1 (전이 판정): 조작 조건 신호를 VC에서 목표 값으로 바꾸면 1초 이내에 단계가 `DONE`이 된다 **[실측 후 수치 조정]**.
- AC-02-2 (이미 목표 상태): 신호가 목표 값인 채로 단계를 시작하면 `DONE`이 되지 않고 `ALREADY_AT_TARGET` 안내가 나온다. 그 상태로 아무리 기다려도 완료되지 않는다.
- AC-02-3 (껐다 켜기): AC-02-2 상태에서 VC로 값을 목표 밖으로 바꿨다가 다시 목표로 돌리면 `DONE`이 된다.
- AC-02-4 (조합 판정): 조작 조건이 충족돼도 유지 조건이 하나라도 안 맞으면 `DONE`이 아니라 `PARTIAL`이고, 충족된 조건과 남은 조건이 각각 표시된다.
- AC-02-5 (유지 조건이 이미 충족): 유지 조건이 시작부터 맞아 있으면 그 조건에 대한 조작을 요구하지 않고 "이미 맞음"으로 표시한다.
- AC-02-6 (오조작 교정): 오조작 규칙에 해당하는 값으로 바꾸면 1초 이내에 교정 안내가 화면과 음성으로 나온다. 오조작을 풀면 교정 안내가 사라진다.
- AC-02-7 (확인 불가): 조회·구독이 실패하면 `UNVERIFIABLE`이 되고 "다시 확인" 버튼이 보인다. 이 상태에서 "다음"으로 넘어가면 그 단계는 `SKIPPED`로 기록된다. (검증: 신호 계층을 실패하도록 바꾼 단위 테스트. VC에는 신호 차단 카드가 없다 **[실측: 에뮬레이터 재현 방법]**)
- AC-02-8 (응답 시간 초과): 초기 상태 확인이 3초 안에 끝나지 않으면 `UNVERIFIABLE`이다.
- AC-02-9 (허위 완료 없음): 사용자가 화면에서 누를 수 있는 "완료" 버튼이 없다. `DONE`은 신호 전이로만 만들어진다.
- AC-02-10 (정리): 단계 종료·화면 이탈·앱 백그라운드 전환 시 모든 구독이 해제되고 폴링이 멈춘다. (검증: 등록·해제 호출 수가 같은지 확인하는 테스트)
- AC-02-11 (무관한 신호): 단계와 관계없는 신호가 바뀌어도 단계 상태가 바뀌지 않는다.
- AC-02-12 (충족이 고정되지 않음): `PARTIAL`에서 조작 조건 신호를 다시 목표 밖으로 바꾸면 `WAITING`으로 돌아간다. 다시 목표로 돌리고 유지 조건이 맞으면 `DONE`이다(POL-J-4).
- AC-02-13 (완료는 되돌리지 않음): `DONE`이 된 뒤 자동 진행을 기다리는 2초 동안 신호가 바뀌어도 `DONE`이 유지된다(POL-J-8).
- AC-02-14 (일부만 읽지 못함): 조건 여러 개 중 하나만 조회에 실패해도 단계는 `UNVERIFIABLE`이다(POL-J-21).

**조정 가능한 값 (초안, 실측 후 확정)**

| 값 | 초안 | 설명 |
|---|---|---|
| 초기 상태 확인 제한 시간 | 3초 | 넘으면 확인 불가 |
| 폴링 간격 | 500ms | 구독이 없는 신호 |
| 힌트 재안내 | 15초 | 전이가 없으면 위치 안내를 한 번 더 읽는다. 자동 실패는 없다 |
| 완료 후 자동 진행 | 2초 | 완료 확인을 읽은 뒤 다음 단계로 |

### FR-03. 코스 목록(홈) — Must

**동작**: 지원되는 코스를 묶음별로 보여 준다. 코스마다 상태(시작 전 / 완료 / 건너뜀 있음)를 표시한다. 소등 확인 진입 버튼이 있다.

**수용 기준**
- AC-03-1: 코스 카드에 이름, 예상 소요 시간, 상태가 보인다.
- AC-03-2: 완료한 코스도 다시 시작할 수 있다.
- AC-03-3: 처음 실행하면 대표 코스(김서림 제거)가 맨 위에 있고 "여기서 시작"으로 강조된다.
- AC-03-4: 화면 어디에도 점수·등급·순위가 없다.
- AC-03-5: 터치 반응이 0.25초 이내다(Pleos 심사 기준).

### FR-04. 단계 진행 화면 — Must

**동작**: 한 화면에 한 단계만 보여 준다. 구성 요소는 안내 문구, 위치 안내 자산, 조건별 충족 표시, 코스 내 진행(예: 2/3), 보조 버튼("다시 듣기", "어디 있어요", "건너뛰기", "그만하기")이다.

**수용 기준**
- AC-04-1: 안내 문구는 한 문장이고 조작 대상의 이름과 위치를 함께 말한다. 예: "운전대 오른쪽 아래, 부채꼴 모양 버튼을 누르세요."
- AC-04-2: 위치 안내 자산에서 대상 버튼이 강조 표시된다.
- AC-04-3: 조합 판정 단계에서는 조건마다 충족/미충족이 따로 표시되고, 신호가 바뀌면 1초 이내에 갱신된다.
- AC-04-4: `DONE`이 되면 완료 표시가 나오고 2초 뒤 다음 단계로 넘어간다. 마지막 단계면 코스 완료 화면(SCR-05)으로 간다.
- AC-04-5: "건너뛰기"를 누르면 그 단계는 `SKIPPED`로 기록되고 다음 단계로 간다. 건너뛴 단계가 있는 코스는 완료로 표시되지 않는다.
- AC-04-6: 음성 진행의 세 어휘와 같은 동작을 하는 터치 버튼이 항상 화면에 있다.
- AC-04-7: 폴링 중인 조건(풍향)에는 "확인 중" 표시가 보인다.
- AC-04-8: 진행 중에 창을 세로형 ↔ 가로형으로 바꿔도 단계와 조건별 충족 상태가 유지된다. 초기 상태 확인을 다시 하지 않는다(POL-E-8).

### FR-05. 음성 안내 (TTS) — Must

**동작**: 단계 시작 시 안내 문구를, 상태가 바뀔 때 상태 문구를 읽는다.

| 시점 | 읽는 내용 |
|---|---|
| 단계 시작 | 안내 문구 |
| `ALREADY_AT_TARGET` | "이미 켜져 있어요. 한 번 껐다가 다시 켜 보세요." |
| `PARTIAL` | 충족된 것과 남은 것. 예: "앞유리 제상 확인. 외기 순환이 남았어요." |
| `CORRECTION` | 교정 안내 문구 |
| `DONE` | 완료 확인. 예: "좋아요. 김서림 제거가 켜졌어요." |
| `UNVERIFIABLE` | "지금은 차량 상태를 확인할 수 없어요." |
| 힌트 재안내 | 위치 안내 문구 |

**수용 기준**
- AC-05-1: 위 표의 모든 시점에 음성이 나온다.
- AC-05-2: 새 음성을 내기 전에 이전 음성을 멈춘다(겹쳐 들리지 않는다).
- AC-05-3: 화면을 떠나거나 실습 UI가 내려가면 음성이 즉시 멈춘다.
- AC-05-4: TTS를 쓸 수 없어도(초기화 실패) 화면 문구만으로 코스를 끝까지 진행할 수 있다.
- AC-05-5: 같은 상태 문구를 3초 안에 반복해서 읽지 않는다(신호가 흔들릴 때 음성이 쏟아지지 않게).
- AC-05-6: ON_DEVICE 모드에서 동작한다(앱 등록 없이 동작하는 모드) **[실측: 에뮬레이터 동작, 한국어 지원]**.

### FR-06. 음성 진행 (STT 고정 어휘) — Must

이 기능이 P02 단독안과의 점수 차를 만든다. 빼지 않는다.

**동작**: STT로 받은 텍스트에서 고정 어휘를 찾아 동작을 실행한다.

| 어휘 | 동작 | 같은 터치 버튼 |
|---|---|---|
| "다음" | 완료된 단계면 다음으로. 미완료 단계면 건너뛸지 한 번 되묻는다("아직 확인되지 않았어요. 건너뛸까요?" → "다음"을 다시 말하면 건너뜀) | 건너뛰기 / 다음 |
| "다시" | 현재 안내 문구를 다시 읽는다 | 다시 듣기 |
| "어디야" | 위치 안내 자산을 강조하고 위치 문구를 읽는다 | 어디 있어요 |

- 매칭은 앱 안에서 한다. 인식된 텍스트에 어휘가 포함돼 있으면 일치로 본다("다음으로", "어디야?" 포함).
- 청취 시작 방식은 **[미정 D5]**: TTS가 끝난 뒤 자동으로 듣기 시작 / 화면의 마이크 버튼. 연속 청취가 되는지 **[실측]** 한 뒤 정한다.
- 차량 마이크 음성을 외부 서비스로 보내지 않는다. STT SDK만 쓴다.

**수용 기준**
- AC-06-1: 대표 코스를 처음부터 끝까지 화면을 터치하지 않고 진행할 수 있다(조작은 VC, 진행은 음성).
- AC-06-2: 세 어휘가 각각 표의 동작을 실행한다.
- AC-06-3: 어휘가 아닌 말은 아무 동작도 일으키지 않는다. 오류 문구도 내지 않는다.
- AC-06-4: 미완료 단계에서 "다음"을 한 번 말하는 것만으로는 건너뛰지 않는다.
- AC-06-5: 앱이 읽는 TTS 음성을 STT가 어휘로 잘못 인식하지 않는다(TTS 재생 중에는 듣지 않는다).
- AC-06-6: STT를 쓸 수 없어도 터치만으로 모든 동작이 가능하다. 마이크가 꺼져 있다는 표시가 보인다.
- AC-06-7: 듣고 있는 동안 화면에 듣는 중 표시가 있다.
- AC-06-8: 한 문장에 어휘가 둘 이상 들어 있으면 아무 동작도 하지 않는다(POL-V-9).
- AC-06-9: 건너뛰기를 되물은 뒤 6초 안에 "다음"이 없으면 되묻기가 취소된다(POL-V-12).
- AC-06-10: "그만하기"와 "기록 지우기"는 음성으로 실행되지 않는다(POL-V-16).

### FR-07. 정차 전용 전환 — Must

**동작**: AAOS `CarUxRestrictionsManager`에 리스너를 등록해 주행 제한을 감지한다. 제한이 걸리면 실습 UI를 내리고 차단 화면(SCR-08)을 보여 준다. 제한이 풀리면 이어서 할지 묻는다.

**수용 기준**
- AC-07-1: 주행 제한이 걸리면 1초 이내에 실습 화면이 사라지고 차단 화면으로 바뀐다. 차단 화면에는 조작할 수 있는 요소가 없다.
- AC-07-2: 동시에 TTS와 STT가 멈춘다.
- AC-07-3: 진행 중이던 코스와 단계 위치가 보존된다. 제한이 풀리면 "이어서 하기"로 같은 단계의 초기 상태 확인부터 다시 시작한다.
- AC-07-4: 주행 제한이 걸린 상태로 앱을 열면 홈이 아니라 차단 화면이 먼저 나온다.
- AC-07-5: 차단 중에는 신호 구독이 해제돼 있다.
- AC-07-6: 주행 제한 리스너를 등록하지 못하면 제한이 걸린 것으로 보고 차단 화면을 보여 준다(POL-D-7). (검증: 단위 테스트)
- AC-07-7: 끊긴 지 30분이 넘으면 "이어서 하기"를 묻지 않고 홈을 보여 준다(POL-R-12).

**[실측]** VC의 기어(P/R/N/D) 주입이 `CarUxRestrictions`에 반영되는지 확인한다. 반영되지 않으면 이 기능은 구현·단위 테스트까지만 하고 시연에서는 빼며, README에 한계로 적는다.

### FR-08. 실습 코스 6종

코스별 정의는 3절에 있다. 모든 코스는 아래 **판정 품질 기준**을 통과해야 빌드에 들어간다.

| # | 판정 품질 기준 | 대응 수용 기준 |
|---|---|---|
| Q1 | 지원 여부를 먼저 확인하고 미지원이면 숨긴다 | AC-01-2 |
| Q2 | 시작 전에 초기 상태를 읽고, 이미 목표면 완료로 치지 않는다 | AC-02-2, AC-02-3 |
| Q3 | 상태가 아니라 전이로 판정한다 | AC-02-1 |
| Q4 | 오조작을 감지해 그 자리에서 교정한다(오조작 규칙이 있는 코스) | AC-02-6 |
| Q5 | 실패·무응답은 확인 불가이고 완료로 치지 않는다 | AC-02-7, AC-02-8 |
| Q6 | 모든 단계에 음성 안내가 있고, 터치와 음성으로 진행된다 | AC-05-1, AC-06-2 |
| Q7 | 주행으로 바뀌면 실습 UI가 내려간다 | AC-07-1 |

**코스 공통 수용 기준**
- AC-08-1: 코스의 모든 단계가 Q1~Q7을 통과한다.
- AC-08-2: 코스의 모든 단계에 기준 차종의 위치 안내 자산이 있다. 자산이 없는 단계가 있는 코스는 빌드에 넣지 않는다.
- AC-08-3: 코스의 신호가 VC에서 주입되고 SDK로 읽히는 것을 실측으로 확인했다(확인 기록을 README 또는 테스트 문서에 남긴다).

### FR-09. 코스 묶음·배지 — Should

**동작**: 코스를 묶음으로 보여 주고, 묶음의 코스를 모두 완료하면 배지를 준다.

| 묶음 (초안 **[미정 D6]**) | 코스 |
|---|---|
| 시야 확보 | CRS-01 김서림 제거, CRS-02 뒷유리 열선·풍량·풍향, CRS-04 와이퍼 |
| 등화 | CRS-03 전조등·미등, CRS-05 방향지시등 |
| 출입 | CRS-06 창문·도어 잠금 |

**수용 기준**
- AC-09-1: 묶음의 모든 코스가 완료(건너뜀 없음)일 때만 배지가 주어진다.
- AC-09-2: 미지원으로 숨겨진 코스는 배지 조건에서 뺀다. 묶음의 코스가 전부 숨겨졌으면 묶음도 숨긴다.
- AC-09-3: 배지는 "완료 표시"다. 숫자 점수, 등급, 다른 사용자와의 비교가 없다.
- AC-09-4: 배지를 받은 뒤 코스를 다시 해도 배지가 사라지지 않는다.

---

### FR-10. 하차 전 소등 확인 — Must

**동작**: 사용자가 홈에서 "소등 확인"을 누르면 하향등·미등·실내등의 현재 상태를 조회해 켜져 있는 등을 알려 준다. 화면이 열려 있는 동안 구독해서 상태가 바뀌면 갱신한다.

**수용 기준**
- AC-10-1: 켜져 있는 등이 있으면 어느 등인지 이름으로 보여 주고 읽어 준다. 예: "실내등이 켜져 있어요."
- AC-10-2: 읽을 수 있는 등이 모두 꺼져 있으면 "확인한 등은 모두 꺼져 있어요"라고 한다. "완전히 소등됐다"고 하지 않는다.
- AC-10-3: 화면에 "주간주행등 등 이 앱이 읽을 수 없는 등이 있습니다"라는 안내가 항상 보인다.
- AC-10-4: 화면이 열려 있는 동안 VC에서 등을 켜고 끄면 1초 이내에 표시가 바뀐다.
- AC-10-5: 조회에 실패한 등은 "확인 불가"로 표시한다. 꺼짐으로 표시하지 않는다.
- AC-10-6: 미지원인 등은 목록에서 빼고, 세 등이 모두 미지원이면 소등 확인 진입 버튼을 숨긴다.
- AC-10-7: 앱이 등을 끄지 않는다. 끄는 방법은 안내만 한다.

---

### FR-11. 진행 기록 저장 — Must

**동작**: 코스별 결과(완료 / 건너뜀 있음 / 시작 전), 단계별 최종 상태, 완료 시각, 배지를 기기 안에 저장한다.

**수용 기준**
- AC-11-1: 앱을 껐다 켜도 코스 상태와 배지가 유지된다.
- AC-11-2: 코스 진행 중에 앱이 백그라운드로 갔다 돌아오면 같은 단계가 보이고, 초기 상태 확인부터 다시 한다(Pleos 심사 기준: 복귀 시 상태 복원).
- AC-11-3: 설정에서 "기록 지우기"를 하면 모든 기록과 배지가 지워진다. 실행 전에 한 번 확인을 받는다.
- AC-11-4: 저장하는 데이터에 개인을 식별하는 정보가 없다. 외부로 전송하지 않는다(앱에 네트워크 퍼미션이 없다).
- AC-11-5: "그만하기"로 나간 시도는 기록되지 않는다. 그 전의 저장 상태가 그대로다(POL-R-6).
- AC-11-6: 완료한 코스를 다시 해서 단계를 건너뛰어도 저장 상태는 "완료"로 남는다(POL-R-7).
- AC-11-7: 소요 시간, 시도 횟수, 교정 횟수가 저장되지 않는다(POL-R-9, POL-S-2).

### FR-12. 오류 처리 — Must

| 상황 | 처리 |
|---|---|
| 차량 서비스 연결 실패 (`ERROR_SERVICE_CONNECTION_FAILURE`) | 연결 오류 화면(SCR-09) + "다시 시도" |
| 퍼미션 거부 (`ERROR_SECURITY_PERMISSION`) | 해당 도메인의 코스를 숨기고, 숨긴 이유를 설정 화면에 표시 |
| 미지원 신호·영역 (`ERROR_NOT_SUPPORTED_*`) | 지원 여부 확인과 같게 처리(코스 숨김) |
| 주행 제한 (`ERROR_DRIVING_RESTRICTED`) | FR-07과 같게 처리 |
| 빈 결과·내부 오류·알 수 없는 예외 | 해당 단계 `UNVERIFIABLE` |
| TTS·STT 초기화 실패 | 음성 없이 진행. 화면에 음성이 꺼져 있다는 표시 |

**수용 기준**
- AC-12-1: 표의 모든 상황에서 앱이 종료되지 않는다.
- AC-12-2: `onFailed`로 `VehicleException`이 아닌 예외가 와도 `UNVERIFIABLE`로 처리된다.
- AC-12-3: 어떤 오류도 단계를 `DONE`으로 만들지 않는다.
- AC-12-4: 오류 문구에 오류코드나 영어 예외 이름이 그대로 보이지 않는다. 사용자가 할 수 있는 행동을 말한다.

### FR-13. 코스 정의 데이터 — Must

**동작**: 코스를 코드가 아니라 데이터 파일로 정의한다. 판정 엔진은 코스 정의를 읽어 동작한다. 차종 확장 비용이 "자산 N장 + 정의 파일 1개"임을 보여 주는 근거가 된다.

정의 형식 예시 (필드 이름은 구현하면서 확정):

```json
{
  "id": "CRS-01",
  "name": "김서림 제거",
  "bundle": "visibility",
  "estimatedSeconds": 60,
  "steps": [
    {
      "id": "CRS-01-S1",
      "instruction": "앞유리 김서림 제거 버튼을 누르세요.",
      "locatorText": "공조 조작부 왼쪽 위, 부채꼴 모양 버튼이에요.",
      "locatorAsset": "ref_model/hvac_front_defrost.png",
      "actionConditions": [
        { "signal": "hvac.frontDefroster", "target": "ON", "label": "앞유리 제상" }
      ],
      "holdConditions": [
        { "signal": "hvac.ac", "target": "ON", "label": "에어컨" },
        { "signal": "hvac.recirculation", "target": "FRESH", "label": "외기 유입" }
      ],
      "misoperations": [
        {
          "when": { "signal": "hvac.recirculation", "is": "RECIRCULATE" },
          "correction": "내기 순환이 켜져 있어요. 외기로 바꿔야 김이 빨리 걷혀요.",
          "locatorAsset": "ref_model/hvac_recirculation.png"
        }
      ],
      "doneText": "좋아요. 김서림 제거가 켜졌어요."
    }
  ]
}
```

**수용 기준**
- AC-13-1: 새 코스를 추가할 때 판정 엔진 코드를 고치지 않는다(새 신호 종류를 쓰는 경우의 신호 어댑터 추가는 예외).
- AC-13-2: 코스 정의에 없는 신호 이름, 빠진 필수 필드가 있으면 빌드 시점 또는 앱 시작 시점에 검증으로 걸러진다. 잘못된 정의가 조용히 무시되지 않는다.
- AC-13-3: 화면 문구와 음성 문구는 모두 코스 정의에서 온다. 코드에 코스별 문구가 박혀 있지 않다.
- AC-13-4: 기준 차종에 묶인 것(위치 문구, 자산 경로)과 차종 공통인 것(신호, 목표)이 정의 안에서 구분된다.

### FR-14. 실습 후 원상 복귀 안내 — Should

**동작**: 코스를 끝냈을 때 실습하느라 켜 둔 것(전조등, 와이퍼 등)이 아직 켜져 있으면 코스 완료 화면에서 알려 준다.

**수용 기준**
- AC-14-1: 코스 완료 시점에 코스가 다룬 신호 중 시작 전과 값이 다른 것을 나열한다.
- AC-14-2: 앱이 대신 되돌리지 않는다. 안내만 한다.
- AC-14-3: 사용자가 되돌리면 1초 이내에 목록에서 사라진다.

### FR-15. 운전자별 진행 기록(프로필) — Could

**동작**: 한 차를 여러 사람이 쓸 때 운전자별로 기록을 나눈다. 이름만 입력하는 기기 내 프로필이다(계정·로그인 없음).

**수용 기준**
- AC-15-1: 프로필을 바꾸면 코스 상태와 배지가 그 프로필의 것으로 바뀐다.
- AC-15-2: 프로필 정보는 기기 밖으로 나가지 않는다.

### FR-16. 후속 조치 안내 — Should

김서림 제거를 했는데도 김이 남아 있을 때 쓰는 기능이다. 지금 공조 상태를 읽어 아직 하지 않은 조치를 순서대로 안내하고, 조치마다 신호로 판정한다. 규칙은 정책서 7A절(POL-F)에 있다.

**앱이 할 수 있는 것과 없는 것**

| | 가능 여부 | 처리 |
|---|---|---|
| 유리에 김이 남았는지 알기 | 불가. 공개 SDK에 습도, 김서림 센서, 외기온, 카메라가 없다 | 사용자에게 묻는다 |
| 지금 공조 상태 읽기 | 가능 | 제상, 최대 제상, 에어컨, 내·외기, 풍량, 목표 온도 |
| 다음 조치 고르기 | 가능 | 코스 정의에 적어 둔 순서에서 아직 안 된 것을 고른다 |
| 조치를 대신 실행 | 하지 않는다 | 사용자가 순정 버튼으로 조작한다(POL-P-3) |

**동작**

1. **진입.** 후속 조치가 정의된 코스에서만 보인다. 진입점은 두 곳이다. (a) 코스 완료 화면(SCR-05)의 "아직 김이 남아 있어요" (b) 코스 소개 화면(SCR-03)의 "김이 잘 안 걷힐 때".
2. **점검.** 기본 조합과 후속 조치에 쓰는 신호를 모두 조회한다.
3. **기본 조합 복구.** 기본 조합(김서림 제거 코스의 목표 상태)이 어긋나 있으면 그것부터 다시 맞추게 한다. 판정은 코스의 해당 단계와 같다.
4. **조치 고르기.** 후속 조치 목록에서 이미 되어 있는 것과 미지원인 것을 빼고, 남은 것 중 첫 번째를 고른다.
5. **조치 안내와 판정.** 고른 조치를 단계 진행 화면(SCR-04)으로 안내한다. 판정은 FR-02와 같다.
6. **해결 확인.** 조치가 완료되면 "김이 걷혔나요?"를 묻는다(SCR-11). "걷혔어요"면 끝낸다. "아직이요"면 2번으로 돌아가 신호를 다시 읽고 다음 조치를 고른다.
7. **마무리.** 남은 조치가 없으면 "앱이 안내할 수 있는 조치는 모두 했어요"라고 알리고 취급설명서와 정비소를 안내한다.

**수용 기준**
- AC-16-1: 후속 조치가 정의되지 않은 코스에는 진입 버튼이 보이지 않는다.
- AC-16-2 (기본 조합 복구): 에어컨이 꺼진 채 시작하면 첫 안내는 후속 조치가 아니라 "에어컨이 꺼져 있어요"다. 에어컨을 켜면 다음으로 넘어간다.
- AC-16-3 (이미 된 조치): VC에서 풍량을 최대로 둔 채 시작하면 "풍량을 가장 세게" 조치가 제안되지 않는다. 그 조치는 완료로 표시되지도 않고 "이미 되어 있어요"로만 보인다(POL-F-4).
- AC-16-4 (미지원): 최대 제상이 미지원이면 그 조치가 목록에 없다.
- AC-16-5 (신호 판정): 조치의 완료는 신호 전이로만 만들어진다. 화면에 "했어요" 버튼이 없다. `ALREADY_AT_TARGET`은 생기지 않는다(이미 된 조치는 고르지 않으므로).
- AC-16-6 (해결 확인): 조치가 완료되면 SCR-11에서 "걷혔어요"와 "아직이요"를 고를 수 있다. 다른 선택지는 "그만하기"뿐이다.
- AC-16-7 (다시 읽기): "아직이요"를 누르면 신호를 다시 조회한 뒤 다음 조치를 고른다. 앞 조치 때문에 차가 함께 바꾼 값(최대 제상을 켜자 풍량이 최대가 된 경우)에 해당하는 조치는 건너뛴다(POL-F-5).
- AC-16-8 (마무리): 남은 조치가 없으면 마무리 문구가 나온다. 문구에 "고장", "이상"이라는 단정이 없다(POL-F-7).
- AC-16-9 (기록 없음): 후속 조치를 하든 안 하든 코스의 저장 상태와 배지가 바뀌지 않는다. 사용자의 응답과 수행한 조치가 저장되지 않는다(POL-F-8).
- AC-16-10 (제어 없음): 후속 조치 안내 중 쓰기 API를 부르지 않는다. "대신 켜 드릴까요" 같은 제안이 없다(POL-F-9).
- AC-16-11 (요청할 때만): 앱이 시간이 지났다고 먼저 묻거나 알림을 보내지 않는다(POL-F-3).
- AC-16-12 (건너뛰기·확인 불가): 조치를 건너뛰면 다음 조치로 간다. 신호를 읽지 못하면 `UNVERIFIABLE`이고 "다시 확인"과 "건너뛰기"가 보인다.
- AC-16-13 (끊김): 주행 제한이나 백그라운드 전환으로 끊기면 이어서 하기를 묻지 않는다. 다시 들어오면 점검부터 한다(POL-F-10).
- AC-16-14 (음성): 조치 안내와 완료 확인은 음성으로도 읽는다. 해결 확인의 답은 터치로만 받는다(고정 어휘는 세 개 그대로).

## 3. 코스 정의

신호 이름은 설명용이다. 실제 메서드명과 값(enum)은 API Reference와 실측으로 확정한다. **모든 코스의 값 범위와 VC 주입 결과는 [실측] 대상이다.**

### CRS-01. 김서림 제거 (대표 코스) — Must · 11-15 ●

| 단계 | 안내 | 조작 조건 | 유지 조건 | 오조작 규칙 |
|---|---|---|---|---|
| S1 | 앞유리 김서림 제거 버튼 누르기 | 앞유리 제상 Off → On | 에어컨 On, 순환 = 외기 | 순환 = 내기 → "외기로 바꿔야 김이 빨리 걷혀요" |

- 목표 조합은 **[미정 D3]**: 기준 차종 취급설명서를 보고 확정한다.
- 제상 버튼을 누르면 차가 에어컨과 외기를 함께 맞춰 주는 차종에서는 버튼 한 번으로 완료된다. 그렇지 않은 차종에서는 `PARTIAL`이 되어 남은 조건을 안내한다. 유지 조건을 "조작"이 아니라 "상태"로 보는 이유다.
- 신호: `getHvacDefrosterState`/`registerHvacDefrosterState`, `getHvacAcState`/`registerHvacAcState`, 내·외기 순환(메서드명 문서 확인)

**코스 수용 기준** (공통 AC-08에 더해)
- AC-CRS01-1: 에어컨 Off·외기 상태에서 VC로 앞유리 제상만 On으로 하면 → `PARTIAL`이고 "앞유리 제상 확인. 에어컨이 남았어요"가 나온다.
- AC-CRS01-2: 그 상태에서 순환을 내기로 바꾸면 → `CORRECTION`이고 교정 안내가 나온다. 순환이 내기인 채로 시작해 제상을 On으로 한 경우에도 `CORRECTION`이 된다.
- AC-CRS01-2b: 순환을 외기로, 에어컨을 On으로 하면 → `DONE`.
- AC-CRS01-2c: 순환이 내기인 채로 시작했고 아직 제상을 켜지 않았으면 교정 안내가 나오지 않는다(`WAITING`).
- AC-CRS01-3: 에어컨 On·외기 상태에서 앞유리 제상을 On으로 하면 → 바로 `DONE`.
- AC-CRS01-4: 세 조건이 모두 맞은 채로 시작하면 → `ALREADY_AT_TARGET`. 제상을 껐다 켜면 `DONE`.

**후속 조치 (FR-16)** — 초안. 내용과 순서는 기준 차종 취급설명서로 확정한다 **[미정 D8]**

| 순서 | 조치 | 목표 | 비고 |
|---|---|---|---|
| F1 | 최대 제상 켜기 | 최대 제상 = On | 지원하는 차종만. 켜면 차가 풍량·온도를 함께 바꿀 수 있고, 그러면 F2·F3은 "이미 되어 있어요"가 된다 |
| F2 | 풍량을 가장 세게 | 풍량 = 지원 범위의 최댓값 | 최댓값은 지원 여부 확인에서 받은 범위로 읽는다 |
| F3 | 온도를 가장 높게 | 목표 온도 = 지원 범위의 최댓값 | 위와 같음 |

- 기본 조합: 앞유리 제상 On + 에어컨 On + 외기 유입 (S1의 목표 상태)
- 신호: `getHvacMaxDefrostState`/`registerHvacMaxDefrostState`, `getHvacFanSpeed`/`registerHvacFanSpeed`, `getHvacTemperature`/`registerHvacTemperature`
- 마무리 문구(초안): "앱이 안내할 수 있는 조치는 모두 했어요. 김이 계속 남으면 취급설명서를 확인하거나 정비소에 문의하세요."
- AC-CRS01-5: 기본 조합이 맞고 최대 제상 Off, 풍량 3, 온도 22℃인 상태에서 시작하면 F1이 먼저 제안된다(최대 제상 지원 시).
- AC-CRS01-6: F1 완료 뒤 "아직이요"를 눌렀을 때 풍량이 이미 최댓값이면 F2를 건너뛰고 F3을 제안한다.

### CRS-02. 뒷유리 열선·풍량·풍향 — Should · 11-15 ○

| 단계 | 안내 | 조작 조건 | 비고 |
|---|---|---|---|
| S1 | 뒷유리 열선 켜기 | 뒷유리 제상 Off → On | 구독 |
| S2 | 풍량 한 단 올리기 | 풍량이 시작 값보다 커짐 (시작 값이 최대면 "한 단 내리기"로 안내를 바꾼다) | 구독. 범위 0~8단(VC 기준) |
| S3 | 바람을 앞유리 쪽으로 | 풍향 = 앞유리(Defrost) | **구독 없음 → 폴링.** "확인 중" 표시 |

- AC-CRS02-1: S2에서 풍량이 시작 값보다 낮아지면 완료되지 않는다.
- AC-CRS02-2: S3에서 VC로 풍향을 바꾸면 폴링 간격 + 1초 이내에 `DONE`이 된다 **[실측: VC 변경이 get에 반영되는지]**. 반영되지 않으면 S3을 코스에서 뺀다.

### CRS-03. 전조등·미등 — Must · 11-15 ○

| 단계 | 안내 | 조작 조건 |
|---|---|---|
| S1 | 미등 켜기 | 미등 Off → On |
| S2 | 전조등(하향등) 켜기 | 하향등 Off → On |
| S3 | 전조등 끄기 (또는 Auto로) | 하향등 On → Off |

- 주간주행등·비상등은 다루지 않는다(SDK 메서드 미확인).
- 신호: `getCurrentTailLampLightState`/`registerTailLampLightState`, `getCurrentLowBeamLightState`/`registerLowBeamLightState`
- AC-CRS03-1: 하향등이 켜진 채로 S2를 시작하면 `ALREADY_AT_TARGET`이 된다(2차 PT 시연 장면).
- AC-CRS03-2: VC의 외부등 모드를 Low beam으로 바꿨을 때 미등과 하향등 상태가 함께 바뀌어도 S1·S2가 각각 올바르게 판정된다 **[실측: 모드와 상태의 관계]**.

### CRS-04. 와이퍼 — Must · 11-15 ○

| 단계 | 안내 | 조작 조건 |
|---|---|---|
| S1 | 와이퍼 켜기 (Low) | 와이퍼 Off → Low |
| S2 | 와이퍼 끄기 | 와이퍼 → Off |

- AC-CRS04-1: S1에서 High나 Auto로 바꾸면 완료가 아니라 "한 단계 낮은 Low로 맞춰 보세요" 안내가 나온다(오조작 규칙) **[실측: 와이퍼 상태 값 목록]**.

### CRS-05. 방향지시등 — Should · 11-15 ○

| 단계 | 안내 | 조작 조건 |
|---|---|---|
| S1 | 왼쪽 방향지시등 켜기 | 방향지시등 = 왼쪽으로 전이 |
| S2 | 오른쪽 방향지시등 켜기 | 방향지시등 = 오른쪽으로 전이 |

- AC-CRS05-1: S1에서 오른쪽을 켜면 완료가 아니라 "반대쪽이에요" 교정 안내가 나온다.
- 비상등은 다루지 않는다.

### CRS-06. 창문·도어 잠금 — Should · 11-15 ○

| 단계 | 안내 | 조작 조건 |
|---|---|---|
| S1 | 운전석 창문 조금 내리기 | 운전석 창문 위치가 시작 값에서 열림 방향으로 변함 |
| S2 | 창문 잠금 켜기 | 창문 잠금 Off → On |
| S3 | 도어 잠그기 | 도어 잠금 = 잠김으로 전이 |

- AC-CRS06-1: S1에서 운전석이 아닌 창문을 내리면 완료되지 않는다 **[실측: 창문 위치의 영역 구분]**.
- 창문·도어를 앱이 움직이지 않는다(쓰기 API 미사용).

### CHK-01. 하차 전 소등 확인 — Must · 11-15 ○

FR-10 참조. 대상 신호: 하향등, 미등, 실내등(`getCurrentCabinLightState`/`registerCabinLightState`).
