# 정책서 — 첫 탑승 조작 실습 (가칭)

- 문서 상태: 초안 v0.1 (2026-11-13)
- 관련 문서: [PRD](01-prd.md) · [용어집](02-glossary.md) · [기능 명세서](03-feature-spec.md) · [사용자 플로우](04-user-flow.md)
- 표기: **[가정]** 은 근거 없이 정한 값, **[미정]** 은 팀 결정이 필요한 항목, **[실측]** 은 에뮬레이터에서 확인한 뒤 확정하는 항목이다.

## 0. 이 문서의 역할

기능 명세서는 기능 하나하나가 **어떻게 동작하는지**를 적는다. 이 문서는 여러 기능에 걸쳐 **항상 같은 답이 나와야 하는 규칙**을 적는다. "이런 경우엔 어떻게 하지?"라는 질문이 나오면 여기서 답을 찾고, 없으면 여기에 추가한다.

| 질문 | 볼 문서 |
|---|---|
| 이 기능을 만드나, 안 만드나 | PRD 5절 |
| 이 기능은 무엇을 하면 완료인가 | 기능 명세서의 수용 기준 |
| **이런 상황에서는 어떻게 처리하나** | **이 문서** |
| 화면이 어떤 순서로 이어지나 | 사용자 플로우 |

- 정책마다 ID(`POL-영역-번호`)가 있다. 코드 주석, 테스트 이름, 리뷰에서 이 ID로 가리킨다.
- 이 문서와 기능 명세서가 어긋나면 **이 문서가 우선**이고, 기능 명세서를 고친다.
- 이용약관과 개인정보 처리방침은 이 문서의 범위가 아니다. 이 앱은 개인정보를 수집하지 않는다(8절). Pleos App Market에 실제로 입점할 때 필요한 문서는 그때 따로 만든다.

## 1. 최상위 원칙

아래 다섯 가지는 다른 모든 정책보다 앞선다. 정책끼리 부딪치면 번호가 앞선 것을 따른다.

| ID | 원칙 | 뜻 |
|---|---|---|
| POL-P-1 | **주행 중에는 아무것도 하지 않는다** | 주행 제한이 걸리면 화면, 음성, 신호 구독을 모두 멈춘다. 예외가 없다 |
| POL-P-2 | **허위 완료를 만들지 않는다** | 확실하지 않으면 완료가 아니다. 완료를 놓치는 것(사용자가 한 번 더 조작)과 허위 완료 중에서는 항상 완료를 놓치는 쪽을 고른다 |
| POL-P-3 | **차량을 제어하지 않는다** | 앱은 읽기만 한다. 켜고 끄는 것은 사용자의 손이 한다 |
| POL-P-4 | **모르면 모른다고 한다** | 신호를 읽지 못한 것을 "꺼짐"이나 "정상"으로 표시하지 않는다 |
| POL-P-5 | **기기 밖으로 아무것도 내보내지 않는다** | 네트워크를 쓰지 않는다 |

## 2. 판정 정책

### 2-1. 전이와 완료

| ID | 정책 | 이유 |
|---|---|---|
| POL-J-1 | 완료는 **신호의 전이**로만 만들어진다. 사용자가 화면에서 완료를 선언하는 수단은 없다 | POL-P-2 |
| POL-J-2 | 단계를 시작할 때마다 조건 신호를 **새로 읽는다**. 앞 단계나 이전 시도에서 읽은 값을 재사용하지 않는다 | 단계 사이에 사용자가 다른 조작을 했을 수 있다 |
| POL-J-3 | **조작 조건**은 두 가지가 모두 참일 때 충족이다. (a) 이번 단계 안에서 목표가 아닌 값 → 목표 값의 전이가 있었다 (b) 지금 값이 목표 값이다 | (a)만 보면 켰다가 바로 끈 경우도 충족이 된다 |
| POL-J-4 | 조작 조건의 충족은 **고정되지 않는다**. 충족된 뒤 값이 다시 목표 밖으로 나가면 미충족으로 돌아간다. 다시 목표로 돌리면 충족이다 | 완료 순간에 차가 실제로 목표 조합이어야 "조합까지 맞게 됐다"가 참이다 |
| POL-J-5 | **유지 조건**은 지금 값이 목표 값이면 충족이다. 전이를 요구하지 않는다 | 차가 스스로 맞춰 주는 조건에 불필요한 조작을 시키지 않는다 |
| POL-J-6 | 단계의 완료 조건은 "모든 조작 조건 충족 + 모든 유지 조건 충족"이 **같은 순간에** 참이 되는 것이다 | |
| POL-J-7 | 유지 조건이 없는 단계는 조작 조건의 전이가 일어난 순간 완료다. 값이 유지되는 시간을 기다리지 않는다 **[실측 후 조정]** | 방향지시등처럼 스스로 꺼지는 신호가 있다 |
| POL-J-8 | **`DONE`은 되돌리지 않는다.** 완료된 뒤 신호가 바뀌어도 그 단계는 완료다 | 완료 후 끄는 것은 정상 행동이다 |
| POL-J-9 | 단계와 관계없는 신호의 변화는 무시한다 | |
| POL-J-10 | "값이 시작 값보다 커짐"처럼 **상대 목표**를 쓰는 단계는 단계 시작 시 읽은 값을 기준으로 한다. 시작 값이 이미 끝값이면 반대 방향으로 안내를 바꾼다 | CRS-02 풍량, CRS-06 창문 |

### 2-2. 이미 목표 상태인 경우

| ID | 정책 |
|---|---|
| POL-J-11 | 시작할 때 조작 조건이 이미 목표 값이면 `ALREADY_AT_TARGET`이다. 완료로 치지 않고 "한 번 껐다가 다시 켜 보세요"라고 안내한다 |
| POL-J-12 | 이 상태에서 자동으로 넘어가거나 일정 시간 뒤 완료로 바꾸지 않는다. 사용자가 직접 전이를 만들거나 건너뛰어야 한다 |
| POL-J-13 | 유지 조건만 이미 맞아 있는 것은 `ALREADY_AT_TARGET`이 아니다. 조건 표시에 "이미 맞음"으로만 보여 준다 |

### 2-3. 오조작과 교정

| ID | 정책 |
|---|---|
| POL-J-14 | 오조작은 코스 정의에 적어 둔 것만 감지한다. 적혀 있지 않은 조작에는 반응하지 않는다 |
| POL-J-15 | 교정 안내는 두 경우에 낸다. (a) 조작 조건이 충족됐는데 오조작 상태가 남아 있다 (b) 단계 진행 중에 신호가 오조작 값으로 바뀌었다 |
| POL-J-16 | 시작할 때부터 오조작 상태였고 아직 조작 조건의 전이가 없으면 교정을 내지 않는다. 주 조작 안내가 먼저다 |
| POL-J-17 | 교정은 **비난하지 않는다.** "틀렸어요"가 아니라 지금 상태와 고치는 방법을 말한다 (10절) |
| POL-J-18 | 오조작이 풀리면 교정 안내를 바로 거둔다. 교정 횟수를 세거나 기록하지 않는다 |

### 2-4. 확인 불가

| ID | 정책 |
|---|---|
| POL-J-19 | 조회 실패, 구독 실패, 응답 시간 초과, 알 수 없는 예외는 모두 `UNVERIFIABLE`이다. 원인을 구분해 사용자에게 보여 주지 않는다 |
| POL-J-20 | `UNVERIFIABLE`에서 "다시 확인"은 횟수 제한이 없다. 자동으로 재시도하지 않는다 |
| POL-J-21 | 조건 여러 개 중 하나만 읽지 못해도 단계 전체가 `UNVERIFIABLE`이다. 읽을 수 있는 조건만으로 완료시키지 않는다 |
| POL-J-22 | 진행 중에 구독이 끊기면 그때까지의 충족 상태를 버리고 `UNVERIFIABLE`로 간다. "다시 확인"을 하면 초기 상태 확인부터 다시 한다 |

### 2-5. 알려진 한계

| ID | 한계 | 처리 |
|---|---|---|
| POL-J-23 | **차가 스스로 바꾼 값과 사용자가 바꾼 값을 구분할 수 없다.** 오토 디포그가 에어컨을 켠 경우가 그렇다 | 구분하지 않는다. 조작 조건에는 사용자가 직접 누르는 버튼의 신호를 두고, 차가 따라 바꾸는 신호는 유지 조건에 둔다. README와 기획서에 한계로 적는다 |
| POL-J-24 | 신호가 바뀌었다는 것만 알 수 있고 **어느 버튼으로** 바꿨는지는 알 수 없다(물리 버튼, 순정 화면, 음성 비서) | 구분하지 않는다. 어느 경로든 사용자가 바꾼 것으로 본다 |
| POL-J-25 | 구독이 없는 신호(풍향)는 폴링 간격만큼 판정이 늦다 | 해당 조건에 "확인 중"을 표시한다 |

## 3. 진행과 기록 정책

### 3-1. 단계와 건너뛰기

| ID | 정책 |
|---|---|
| POL-R-1 | 한 화면에는 한 단계만 있다. 단계는 코스 정의의 순서대로만 진행한다. 뒤로 가는 기능은 없다 |
| POL-R-2 | 어떤 상태에서든 건너뛸 수 있다. 건너뛴 단계는 `SKIPPED`로 기록한다 |
| POL-R-3 | 건너뛰기에는 이유를 묻지 않는다 |
| POL-R-4 | 음성으로 미완료 단계를 건너뛰려면 "다음"을 두 번 말해야 한다(한 번 말하면 되묻는다). 터치는 한 번이면 된다 | 

### 3-2. 코스 결과

| ID | 정책 |
|---|---|
| POL-R-5 | 코스의 한 번 시도 결과는 셋 중 하나다. **완료**(모든 단계 `DONE`) / **건너뜀 있음**(하나라도 `SKIPPED`) / **중단**(끝까지 가지 않음) |
| POL-R-6 | "그만하기"로 나가면 그 시도는 **중단**이고 기록하지 않는다. 그 시도에서 완료한 단계도 남기지 않는다 |
| POL-R-7 | 코스의 저장 상태는 **지금까지 가장 좋은 결과**다. 순서는 완료 > 건너뜀 있음 > 시작 전. 완료한 코스를 다시 해서 건너뛰어도 "완료"로 남는다 |
| POL-R-8 | 완료한 코스는 언제든 다시 할 수 있다. 다시 할 때는 처음부터 한다 |
| POL-R-9 | 걸린 시간, 시도 횟수, 교정 횟수는 저장하지 않는다 | 

POL-R-9의 이유: 이 값들은 점수처럼 읽힌다(PRD "하지 않는 것"). 사용성 테스트의 측정은 앱 기능이 아니라 관찰로 한다.

### 3-3. 이어서 하기

| ID | 정책 |
|---|---|
| POL-R-10 | 주행 전환이나 백그라운드 전환으로 끊긴 코스는 **코스와 단계 위치**만 기억한다. 단계 안의 충족 상태는 기억하지 않는다 |
| POL-R-11 | 돌아오면 같은 단계의 초기 상태 확인부터 다시 한다 (POL-J-2) |
| POL-R-12 | 끊긴 지 30분이 넘으면 이어서 하기를 묻지 않고 홈을 보여 준다 **[가정]** |
| POL-R-13 | 앱이 종료됐다가 다시 실행되면 이어서 하기를 묻지 않는다. 완료 기록과 배지는 남아 있다 |

### 3-4. 묶음과 배지

| ID | 정책 |
|---|---|
| POL-R-14 | 배지는 묶음에서 **보이는 코스**가 모두 "완료"일 때 준다. 건너뜀 있음은 완료가 아니다 |
| POL-R-15 | 미지원이라 숨겨진 코스는 배지 조건에서 뺀다. 묶음의 코스가 전부 숨겨졌으면 묶음도 숨긴다 |
| POL-R-16 | 준 배지는 거두지 않는다. 사용자가 "기록 지우기"를 할 때만 사라진다 |
| POL-R-17 | 배지에는 숫자, 등급, 날짜 경쟁, 다른 사용자와의 비교가 없다 |
| POL-R-18 | 화면의 "1/3" 같은 숫자는 **현황**이다. 백분율, 게이지, 순위로 바꿔 보여 주지 않는다 |

## 4. 코스 노출 정책

| ID | 정책 |
|---|---|
| POL-C-1 | 코스의 필수 신호 중 하나라도 미지원이면 코스 전체를 숨긴다. 일부 단계만 빼고 보여 주지 않는다 |
| POL-C-2 | 퍼미션이 거부된 도메인의 코스도 숨긴다 |
| POL-C-3 | 숨긴 코스와 이유는 설정 화면에서 볼 수 있다. 홈에서는 흔적을 보이지 않는다 |
| POL-C-4 | 지원 여부는 **앱을 시작할 때마다** 다시 확인한다. 저장해 두지 않는다 |
| POL-C-5 | 홈의 순서는 고정이다. 묶음 순서는 시야 확보 → 등화 → 출입, 묶음 안에서는 코스 번호 순이다. 완료 여부로 순서를 바꾸지 않는다 **[미정 D6]** |
| POL-C-6 | 기록이 하나도 없을 때만 대표 코스(김서림 제거)를 "여기서 시작"으로 강조한다 |
| POL-C-7 | 위치 안내 자산이 없는 단계가 하나라도 있는 코스는 빌드에 넣지 않는다 |

### 코스로 만들 수 있는 조작의 기준

새 코스를 넣을 때 아래 넷을 모두 만족해야 한다.

| ID | 기준 | 이 기준으로 뺀 예 |
|---|---|---|
| POL-C-8 | **정차 중에 안전하게** 할 수 있다 | 기어, 크루즈 컨트롤 |
| POL-C-9 | 결과를 **읽을 수 있는 신호**가 SDK 문서에 있다 | 주간주행등, 비상등, 주유구, 시동 |
| POL-C-10 | 조작을 **되돌릴 수 있고**, 되돌리지 않아도 해가 없다 | 초기화, 설정 삭제류 |
| POL-C-11 | 주변 사람이나 차에 **위험·불편을 주지 않는다** | 경적, 상향등을 켠 채 두기 |

## 5. 음성 정책

### 5-1. 음성 안내 (TTS)

| ID | 정책 |
|---|---|
| POL-V-1 | 화면에 보이는 것과 **같은 문구**를 읽는다. 음성에만 있는 정보는 없다 |
| POL-V-2 | 새 음성이 나올 때 재생 중인 음성은 끊는다. 쌓아 두지 않는다 |
| POL-V-3 | 같은 문구를 3초 안에 다시 읽지 않는다 |
| POL-V-4 | 상태가 연달아 바뀌면 **마지막 상태**의 문구만 읽는다 |
| POL-V-5 | 힌트 재안내는 단계마다 한 번만 한다(15초 뒤). 그 뒤로는 사용자가 "다시"나 "어디야"를 요청할 때만 읽는다 |
| POL-V-6 | 음성 안내를 끄면 화면 문구만으로 진행한다. 효과음으로 대신하지 않는다 **[가정]** |
| POL-V-7 | 다른 앱이 소리를 내고 있으면 안내하는 동안만 잠깐 양보받는다(일시적 오디오 포커스). 미디어를 멈추거나 끄지 않는다 **[실측]** |

### 5-2. 음성 진행 (STT)

| ID | 정책 |
|---|---|
| POL-V-8 | 인식하는 말은 "다음", "다시", "어디야" 세 가지다. 인식된 문장에 이 말이 들어 있으면 일치로 본다 |
| POL-V-9 | 한 문장에 어휘가 둘 이상 들어 있으면 **아무것도 하지 않는다** |
| POL-V-10 | 어휘가 아닌 말, 인식 실패, 무음에는 반응하지 않는다. 오류 문구도 내지 않는다 |
| POL-V-11 | 음성 안내가 재생되는 동안에는 듣지 않는다 |
| POL-V-12 | 건너뛰기를 되물은 뒤 6초 안에 "다음"이 없으면 되묻기를 취소하고 원래 상태로 돌아간다 **[가정]** |
| POL-V-13 | 듣고 있을 때는 항상 화면에 표시한다. 표시 없이 듣지 않는다 |
| POL-V-14 | 인식한 말과 음성은 **저장하지 않는다.** 차량 마이크 음성을 외부로 보내지 않는다(공모전 규정) |
| POL-V-15 | 음성으로 할 수 있는 것은 터치로도 모두 할 수 있다. 음성으로만 되는 기능은 없다 |
| POL-V-16 | 음성으로는 **파괴적인 동작을 하지 않는다.** 기록 지우기, 그만하기는 터치로만 한다 |

POL-V-9의 이유: "다음 말고 다시"처럼 뜻이 반대일 수 있다. 잘못 넘기는 것보다 반응하지 않는 편이 안전하다(POL-P-2).

## 7. 소등 확인 정책

| ID | 정책 |
|---|---|
| POL-L-1 | 대상은 하향등, 미등, 실내등이다. 읽을 수 없는 등은 대상이 아니고, 그 사실을 화면에 항상 적는다 |
| POL-L-2 | 모두 꺼져 있을 때의 문구는 "확인한 등은 모두 꺼져 있어요"다. "소등 완료", "모두 꺼졌습니다", "안심하세요" 같은 단정을 쓰지 않는다 |
| POL-L-3 | 읽지 못한 등은 "확인 불가"다. 꺼짐으로 표시하지 않는다 (POL-P-4) |
| POL-L-4 | 미지원인 등은 목록에서 뺀다. 셋 다 미지원이면 소등 확인 자체를 숨긴다 |
| POL-L-5 | 소등 확인은 사용자가 열었을 때만 동작한다. 앱이 먼저 알리거나, 백그라운드에서 감시하거나, 하차를 감지해 띄우지 않는다 |
| POL-L-6 | 소등 확인 결과는 저장하지 않는다 |
| POL-L-7 | 켜져 있는 것은 "문제"가 아니라 "상태"로 말한다. 일부러 켜 둔 것일 수 있다 |

POL-L-5의 이유: 앱이 실행되지 않을 때의 알림과 백그라운드 실행은 플랫폼 문서가 보장하지 않는다. 주차 뒤 전원 상태에서 신호가 유지되는지도 확인되지 않았다.

## 9. 오류와 앱 상태 정책

| ID | 정책 |
|---|---|
| POL-E-1 | 어떤 오류도 단계를 완료로 만들지 않는다 (POL-P-2) |
| POL-E-2 | 오류 화면에는 **무슨 일이 있었는지 + 사용자가 할 수 있는 행동**을 적는다. 오류코드, 예외 이름, 영어 메시지를 보여 주지 않는다 |
| POL-E-3 | 차량 연결 실패는 자동으로 다시 시도하지 않는다. 사용자가 "다시 시도"를 눌렀을 때만 한다 |
| POL-E-4 | 음성 기능의 실패는 앱 사용을 막지 않는다. 음성 없이 계속한다 |
| POL-E-5 | 코스 정의가 잘못됐으면(없는 신호 이름, 빠진 필드) 그 코스를 조용히 숨기지 않는다. 빌드나 앱 시작 단계에서 오류로 드러낸다 |
| POL-E-6 | 백그라운드로 가면 구독, 폴링, 음성을 모두 멈춘다. 백그라운드에서 하는 일은 없다 |
| POL-E-7 | 앱은 알림을 보내지 않는다 |
| POL-E-8 | 창 크기나 방향이 바뀌어도(세로형 ↔ 가로형) 진행 중인 단계와 충족 상태를 유지한다. 초기 상태 확인을 다시 하지 않는다 |

POL-E-8과 POL-R-10의 차이: 창 크기 변경은 앱이 계속 포그라운드에 있어 구독이 끊기지 않는다. 백그라운드 전환은 구독이 끊긴다.

## 13. 정책을 바꿀 때

1. 바꾸려는 정책의 ID와 이유를 팀에 먼저 알린다.
2. 1절의 최상위 원칙을 바꾸는 것은 PRD 범위를 바꾸는 것과 같다. 팀 전원이 합의해야 한다.
3. 이 문서를 고친 뒤 기능 명세서의 수용 기준과 코스 정의를 맞춘다.
4. `[가정]`을 실측이나 테스트로 확인했으면 표시를 지우고 근거를 한 줄 적는다.
5. 정책 ID는 다시 쓰지 않는다. 없앤 정책은 지우지 말고 "폐지"로 표시한다.
