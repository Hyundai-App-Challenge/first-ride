# QA 도구의 앱 대상 지정

로컬 debug 패키지를 별도로 설치해도 기존 release 데이터를 보존하며 같은 QA 도구로 검증한다.

## 성공 기준
- APP_ID로 지정한 앱의 신호원과 Activity만 변경·실행한다.
- 설치 실패 시 기존 앱을 삭제하지 않는다.
- 기본 패키지와 QA 패키지의 회귀 테스트가 통과한다.

## 범위와 순서
1. 대상 패키지·Activity를 공통으로 해석하고 세 스크립트에 적용한다(10분).
2. 자동 삭제를 없애고 실패·성공 경로를 테스트한다(10분).
3. 연결된 에뮬레이터에서 QA 패키지 신호 전환을 확인하고 PR·병합한다(10분).

앱 판정·화면·release 코스 범위는 변경하지 않는다. APP_ID를 생략하면 기존 com.firstride를 유지한다.

사용 스킬: plan·verify(완료 조건과 실행 증거), ponytail·karpathy-guidelines(기존 구조에 맞춘 최소 변경).


# W-50 STT 요청 격리

종료 이벤트 뒤 도착한 최종 텍스트가 다음 듣기를 완료하는 문제를 막는다.

## 성공 기준
+- 종료 뒤 최종 텍스트는 같은 요청이 받고, 이전 요청의 늦은 콜백은 다음 요청을 완료하지 않는다.
+- 실패·취소·시간 초과·동시 요청에도 SDK가 정리되고, 정리 완료 전 다음 SDK를 시작하지 않는다.
+- 회귀 테스트와 실제 SDK 연속 요청·취소 검증을 통과한다.
+
+순서: SDK 경계에서 콜백 순서를 재현(10분) → 요청별 소유·정리 구현(10분) → 실제 에뮬레이터와 전체 테스트 검증(10분).
+
+앱의 STT 활성화와 세 어휘 실사용 정확도는 별도 게이트다. 공개 SttPort는 변경하지 않는다.
+
+결정: 임의의 콜백 대기 시간을 두는 대신 요청마다 SDK를 만든다. 요청 ID가 없기 때문이며, SDK 경계만 가짜 인식기로 바꿔 늦은 콜백을 검증한다. 실제 연속 요청의 초기화→request는 이번 샘플에서 122/2/37ms였다(최초 차가운 연결은 약 1.3초). 추가 초기화 비용은 실사용 게이트에서 다시 확인한다.
