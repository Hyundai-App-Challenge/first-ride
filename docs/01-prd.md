## 1. 한 문장 정의

처음 타는 차에서 출발 전 정차 상태로 순정 버튼을 직접 조작하면, 앱이 차량 신호를 읽어 **"찾았고, 조합까지 맞게 됐다"** 를 판정해 주는 차량 내 실습 앱.

## 2. 해결하려는 문제

### 2-1. 문제

새 차나 렌터카를 처음 타는 운전자는 김서림 제거, 전조등, 와이퍼 같은 기본 기능의 위치와 조작법을 모른 채 출발한다. 기존 안내 수단은 모두 "알려 주기"에서 끝난다.

| 기존 수단 | 한계 |
|---|---|
| 종이·웹 취급설명서 | 읽지 않는다. 화면 메뉴 경로 위주라 실제 버튼을 찾는 데는 도움이 약하다 |
| 제조사 안내 앱(Hyundai/Genesis Virtual Guide, Kia AI 오너스 매뉴얼) | 영상·AR로 위치를 보여 주기만 한다. 사용자가 실제로 해 봤는지, 맞게 됐는지는 모른다 |
| 렌터카 QR 안내, 인도 시 구두 설명 | 한 번 듣고 잊는다. 인도 뒤 후속 설명은 대부분 받지 못한다 |
| 음성 비서(Gleo AI) | 대신 제어해 줄 뿐, 운전자가 버튼 위치를 익히게 하지는 않는다. 주행 상황에 따라 명령이 제한될 수 있다 |

핵심 공백은 **"조작 결과의 확인"** 이다. 폰 앱은 차의 상태를 모르기 때문에 사용자가 맞게 조작했는지 판정할 수 없다. 차량 신호를 읽을 수 있는 차량 내 앱만 이 공백을 메울 수 있다.

| 구분 | 사용자 | 상황 | 우선순위 |
|---|---|---|---|
| 1차 | **신차 오너** (Pleos Connect 탑재 차량을 처음 받은 운전자) | 인도 직후 첫 며칠. 주차장·집 앞에서 정차 상태 | MVP 대상 |
| 1차 | **같은 차를 함께 쓰는 가족·동승 운전자** | 차주가 아닌 사람이 처음 운전대를 잡을 때 | MVP 대상 |
| 2차 | 렌터카·카셰어링 이용자 | 인수 직후 출발 전 | 확대 계획 (렌터카 차량의 Pleos 앱 설치 가능 여부 미확인) |

대표 사용자 시나리오:

> 지현(29)은 생애 첫 차를 인도받았다. 비 오는 날 앞유리에 김이 서렸는데 어떤 버튼을 눌러야 하는지 몰라 히터만 세게 틀었다. 다음 날 주차장에서 앱을 켜고 "김서림 제거" 코스를 시작한다. 앱이 버튼 위치를 그림으로 보여 주고, 지현이 버튼을 누르자 "앞유리 제상 확인"이라고 말해 준다. 내기 순환이 켜져 있어 "외기로 바꿔야 김이 빨리 걷힙니다"라는 안내가 이어지고, 바꾸자 코스가 완료된다.

## 4. 핵심 가치

1. **신호로 판정한다.** 사용자가 "했다"고 누르는 자기체크가 아니라, 차량 신호가 실제로 바뀌었을 때만 완료로 본다.
2. **찾는 것부터 조합까지.** 버튼 하나의 위치뿐 아니라 여러 상태가 함께 맞아야 하는 조작(김서림 제거)을 판정하고, 틀린 조합은 그 자리에서 교정한다.
3. **모르면 모른다고 한다.** 신호를 읽지 못하면 "확인 불가"로 표시하고 완료 처리하지 않는다. 처음부터 목표 상태였던 경우도 완료로 치지 않는다.
4. **안 되면 다음 수를 알려 준다.** 김서림 제거를 켰는데도 김이 남아 있으면, 지금 차의 공조 상태를 읽어 아직 하지 않은 조치를 순서대로 안내한다.
5. **손과 눈은 버튼에.** 조작하는 동안 화면을 보지 않아도 되도록 음성으로 안내하고(TTS), 음성으로 단계를 넘긴다(STT).
6. **정차 중에만.** 주행 상태가 되면 실습 화면을 내린다.

## 5. 제품 범위

### 5-1. 이번에 만드는 것 (In scope)

| 영역 | 내용 |
|---|---|
| 판정 엔진 | 지원 여부 확인 → 초기 상태 확인 → 전이 판정 → 조합 판정 → 오조작 교정 → 확인 불가 처리 |
| 실습 코스 6종 | 김서림 제거(대표) / 뒷유리 열선·풍량·풍향 / 전조등·미등 / 와이퍼 / 방향지시등 / 창문·도어 잠금 |
| 하차 전 소등 확인 | 하향등·미등·실내등이 켜져 있는지 읽어 알려 줌 |
| 음성 진행 | TTS 단계 안내·완료 확인, STT 고정 어휘("다음", "다시", "어디야") |
| 코스 묶음·배지 | 코스 완료 기록과 묶음 단위 배지 |
| 후속 조치 안내 | 김서림 제거를 했는데도 김이 남아 있을 때, 지금 공조 상태를 읽어 아직 하지 않은 조치를 순서대로 안내하고 신호로 판정 |
| 정차 전용 전환 | 주행 제한이 걸리면 실습 UI를 내리고, 풀리면 이어서 진행 |
| 코스 정의 데이터 | 신호·목표·오조작 규칙·위치 안내 자산을 코드와 분리한 데이터로 관리 |
| 기준 차종 1종 | 위치 안내 그림을 직접 제작 **[미정: 기준 차종]** |

### 5-2. 이번에 하지 않는 것 (Out of scope)

범위가 늘어나는 것을 막기 위해 명시한다. 아래 항목은 요청이 와도 이번 공모전 범위에서는 추가하지 않는다.

| 하지 않는 것 | 이유 |
|---|---|
| **차량 제어(쓰기 API)** — 앱이 대신 공조·조명을 켜고 끄는 것 | 제품의 핵심이 "사용자의 실제 조작"이다. 제어 퍼미션(`CONTROL_CAR_*`)도 쓰지 않는다 |
| **주행 중 사용** | 정책상 "차량 설정"·"매뉴얼"류는 주행 중 금지. 주행 중에는 화면을 내린다 |
| **점수·등급·랭킹** | 공식 예시 "안전운전 점수"와 겹쳐 보인다. 표시는 "조작 완료"와 배지까지만 |
| **내비·위치 연동** (NaviHelper, FusedLocation) | 에뮬레이터 동작이 미확인. 핵심 가치에 필요 없다 |
| **기어·시동·주차 브레이크·주유구·충전구 코스** | 읽기 신호가 문서에 없거나 불명확하다 |
| **주간주행등·비상등·제동등 판정** | SDK 메서드가 확인되지 않았다 |
| **완전 소등 인증** | 조회할 수 없는 등이 있다. 소등 확인은 "읽을 수 있는 등의 상태"만 알려 준다 |
| **다차종 콘텐츠** | 기준 차종 1종을 끝까지 완성한다. 차종 확장은 구조(데이터 분리)로만 보여 준다 |
| **계정·서버·클라우드 동기화** | 모든 데이터는 기기 안에만 저장한다. 외부 네트워크 호출 없음 |
| **Gleo AI 연동** (Gleo Interface) | 공모전 참가팀은 신청할 수 없다 |
| **자유 발화 음성 명령** | STT는 고정 어휘 3개만 매칭한다 |
| **김서림 자동 감지** | 유리에 김이 남았는지 알 수 있는 신호(습도, 김서림 센서, 외기온, 카메라)가 공개 SDK에 없다. 김이 걷혔는지는 사용자에게 묻는다 |
| **후속 조치를 앱이 대신 실행** | 공조 쓰기 API는 있지만 쓰지 않는다. 이유는 차량 제어와 같다 |
| **AI가 상황을 보고 추천** | Pleos LLM SDK는 공모전 기간에 제공되지 않고, 이 앱은 네트워크를 쓰지 않는다. 추천은 정해 둔 규칙으로만 한다 |
| **카메라·AR 버튼 인식** | 카메라 API가 문서에 없다 |
| **렌터카 사업자용 관리 화면(B2B 콘솔)** | 확대 계획으로만 기획서에 적는다 |
| **영상 튜토리얼** | 정보 제공형과 차별점이 흐려진다. 주행 중 영상 제한도 있다 |

### 5-3. 향후 계획 (기획서에만 기재)

- 차종 추가: 코스 정의 데이터 + 위치 안내 자산만 추가하는 구조
- 렌터카·카셰어링 제휴: 인수 직후 실습, 사업자별 코스 구성
- 운전자별 진행 기록(한 차를 여러 사람이 쓰는 경우)
- Gleo AI 연동("김서림 제거 어디 있어?"에 앱이 응답)

## 6. 성공 지표

### 6-1. 제품 지표 (출시 후를 가정한 KPI) **[가정]**

| 지표 | 정의 | 비고 |
|---|---|---|
| 첫 탑승 세션 수 | 차량당 최초 실습 세션이 시작된 수 | 기획서의 MAU 추정 근거 |
| 코스 완료율 | 시작한 코스 중 신호 판정으로 완료된 비율 | 핵심 지표 |
| 세션당 완료 코스 수 | 한 세션에서 완료한 코스 수 | |
| 재방문 | 같은 차량에서 다른 날 다시 연 비율 | 운전자가 바뀔 때, 소등 확인 사용 시 |

기획서에는 확인된 수치와 가정을 한 표에서 분리해 적는다. 확인된 수치: 2025년 신규 등록 169.5만 대([뉴시스](https://mobile.newsis.com/view/NISX20260128_0003493411)), 렌터카 인가 약 131만 대(2026년 1분기 말, 단기·장기 구분 없음, [세계일보](https://www.segye.com/newsView/20260821502771)), Pleos Connect 탑재 차종 보도(더 뉴 그랜저 등, [현대차그룹](https://www.hyundaimotorgroup.com/ko/story/pleos-connect-next-generation-infotainment-system), [이코노미스트](https://economist.co.kr/article/view/ecn202609070001)). 가정: Pleos 탑재 비율, 렌터카 탑재 여부.

### 6-2. MVP 완료 기준 (2차 PT 시연본이 만족해야 하는 것)

| # | 기준 | 측정 방법 | 목표 |
|---|---|---|---|
| M1 | **허위 완료 0건** | 초기값이 이미 목표인 경우, 신호 실패, 미지원 신호의 테스트 케이스 전부 | 0건 |

| M7 | 6개 코스 + 소등 확인 모두 판정 품질 기준 통과 | 기능 명세서의 수용 기준 | 전부 통과 |

### 6-3. 검증 계획 (기획서의 "효과 검증" 항목)

같은 안내를 주고 **자기체크 방식**(사용자가 "했어요"를 누름)과 **신호 판정 방식**을 비교한다. 측정: 허위 완료율(실제로는 안 됐는데 완료로 넘어간 비율), 도움 요청 횟수, 코스당 시간. 2차 PT 전 소규모(5~10명)로 실시하고 결과를 발표에 쓴다 **[가정: 일정 여유]**.

## 9. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 에뮬레이터가 팀 장비에서 돌지 않음(전용 GPU 필수) | 개발·시연 불가 | 하드웨어는 충족(RTX 3060 12GB 보유). 설치와 실행을 가장 먼저 확인. 장비가 한 대면 에뮬레이터 작업이 그 PC에 몰린다 |

| "현대·기아가 이미 해 봤다" | 창의성 감점 | 선행 사례 비교표를 기획서에 먼저 싣는다. "최초"라고 쓰지 않는다 |
| 실차에서 오토 디포그 등 자동 상태 변경이 사용자 조작으로 오검출 | 실서비스 품질 | 한계로 명시하고 대응 설계(조작 조건·유지 조건 구분)를 적는다 |
| 사업성 근거 공백(국내 수요 규모, 렌터카 탑재) | 사업성 감점 | 확인된 수치와 가정을 분리 표기. 검증 계획으로 보완 |
